# ADR-0022: Typed subworkflow invocation is deferred

- Status: Accepted
- Date: 2026-08-25
- Source: Issue #74

## Decision

Defer typed subworkflow invocation as a future docs-only design. The current
`IrNodeKind` set remains closed: `Agent`, `Action`, `Validator`, `Registered`,
`Approval`, and `Terminal`. A future typed invocation must use registered nodes
per ADR-0004 rather than adding a second IR or wiring an invoke engine into
`workflow-ir` or runtime.

Prototype sketch, intentionally not wired into the product:

```rust
struct TypedInvoke<Input, Output> {
    node: RegisteredNode,
    _input: PhantomData<Input>,
    _output: PhantomData<Output>,
}

fn invoke<Input, Output>(call: TypedInvoke<Input, Output>, input: Input) -> Output;
```

## Reason

The existing closed node set has no subworkflow kind, and ADR-0004 already
assigns unsupported logic to registered nodes or handwritten ADK graph code.
The sketch records the type shape without creating a second invocation model.

## Consequence

Issue #74 has prototype evidence and an explicit defer decision. Typed
invocation remains unavailable in the current IR and runtime; a future design
must first define registered-node contracts and their validation boundary.
