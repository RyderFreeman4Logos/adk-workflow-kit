# ADR-0023: Isolate ADK-Rust 2.1 graph ownership at the integration boundary

- Status: Accepted
- Date: 2026-08-26
- Source: Issue #170

## Decision

Adopt ADK-Rust 2.1.0 graph construction and execution only inside an isolated
spike/member until the workspace-wide upgrade is handled by Issue #171. Keep
canonical IR, persisted schemas, lock-owned domain records, and project-owned
events independent of ADK implementation types.

| Capability | Decision | Boundary |
|---|---|---|
| Graph execution | Adopt | Use `GraphAgent`, `AgentNode`, `START`, `END`, and conditional edges in the ADK adapter boundary. Do not add a second scheduler. |
| Checkpointer | Wrap | Expose a project-owned checkpoint contract later; do not persist ADK checkpoint types in domain artifacts. |
| Retry/timeout | Wrap | Translate bounded policy at the adapter boundary; do not let ADK policy types enter canonical IR. |
| Confirmation | Keep | Tool approval remains project-owned default-deny policy; an ADK graph cannot authorize a denied tool. |
| Sandbox | Keep | Per-run workdir and network-deny rules remain project-owned; ADK execution does not replace the verified sandbox. |
| Events | Wrap | Map ADK runtime observations to project-owned events; never persist ADK event implementation types. |

## Reason

The published stable pin is `adk-rust =2.1.0`, while the current workspace
remains on edition 2021, MSRV 1.94.0, and `adk-rust =1.0.0`. The isolated
member permits direct ownership evidence without upgrading unrelated crates.
ADK supplies graph mechanics, while the kit retains authority over durable
identity, policy, schemas, and side effects.

## Consequences

The spike proves the minimum integration shape and its fail-closed behavior.
The workspace-wide dependency and toolchain migration is explicitly deferred
to Issue #171. No ADK implementation type is part of canonical IR, persisted
schema, lock-owned domain data, or project-owned event contracts.

## Executable Spike

The spike is at `spikes/adk-2-1-ownership` and constructs:

`START -> fake planner AgentNode -> fake typed tool -> conditional route`

The route map declares `pass -> success` and `fail -> abstention`. The tool
uses a typed `ToolInput`/`ToolOutput` pair and a default-deny boolean. An
undeclared router result fails as `GraphError::UnknownRouteTarget`; denial
returns before the tool call counter can advance.

Evidence, run from the frozen feature branch:

```text
$ just lock
Locked 229 packages; adk-rust/adk-graph 2.1.0 resolved; exit 0

$ just m1-01-red
Initially blocked by the required lock refresh; after `just lock`, the RED
run reached compilation and reported rustc 1.94.0 < package requirement 1.95.

$ just m1-01-green
ionice -c 3 cargo +1.98.0 test -p adk-2-1-ownership --locked
running 4 tests
4 passed; 0 failed
Doc-tests: 0 passed; 0 failed
```

The `+1.98.0` toolchain is used only by the isolated recipe so the workspace
MSRV and edition are unchanged. The test module covers real graph execution,
deterministic undeclared-route rejection, denial before execution, and a
serde-only persisted boundary containing no ADK implementation value.
